# `Clean.ps1` 独立 Windows 清理

本脚本是当前包内完整自包含的 Windows 实现，不读取环境配置仓库中的 `clean.command`、macOS 源码或其它功能包。需要 Windows PowerShell Desktop 5.1 与交互控制台，不提权，不下载工具，不注册菜单，不修改全局执行策略。

从磁盘容量菜单点击后，系统 PowerShell 在独立控制台打开本脚本，结束后控制台保留供查看结果。也可从本目录运行 `powershell.exe -NoLogo -NoProfile -STA -File ./Clean.ps1`。`-Mode Plan -Category cache/history/build-apps/avd/shortcuts` 只预览；涉及工程时显式传入 `-ProjectRoot`。默认模式为 `Interactive`，非交互执行被拒绝；加载函数供隔离测试时不执行业务。

首先询问是否进入开发分组：只按回车继续，输入任意内容后回车跳过；输入结束取消整轮，不再进入常规 clean。只有继续且已有健康 `fzf` 后，才选择组并收集该组候选。未安装或损坏的 `fzf` 会保留整个开发阶段，不自动安装，不回退数字菜单。

询问句在已知支持虚拟终端的交互 ConsoleHost 中显示为青色粗体；仅回车选项为绿色粗体，任意／非空输入选项为红色粗体，分隔符恢复普通样式。没有这两类输入选项的菜单询问也突出正文。`NO_COLOR` 存在（含空值）、输入／输出重定向、纯文本模式、Sourcetree 或未知宿主／终端能力时保留相同文案并降级纯文本；不为展示改变控制台模式、读取和取消语义。日志只保存纯文本，Windows 原生对话框继续使用系统外观。

| 原 macOS 开发组 | Windows 对应项与边界 |
| --- | --- |
| Device Support | 不适用，不查找或删除 Apple / Android SDK。 |
| Simulators | 当前用户默认 `.android/avd` 中实体 `.avd` 目录确实缺失的精确 `.ini` 登记；不清理完整模拟器、共享镜像或 SDK。 |
| SwiftUI Previews | 不适用，不伪造 Apple API 或扫描同名目录。 |
| DerivedData | 用户明确选择的 Flutter 根工程中 `build/windows/{x64,arm64,x86}/runner/{Debug,Profile,Release}` 且含实际 EXE 的标准输出。先完整备份，不清理任意 `build`、`.gradle`、`node_modules` 或依赖目录。 |
| Archives | 用户明确选择的 Flutter 工程 `build/app/outputs/apk` / `bundle` 内实际 APK / AAB 文件，逐文件列出、选择、备份，不删除整个 outputs 或把交付包自动视为缓存。 |
| Caches | 当前用户 `D3DSCache`、`pip/Cache`、`npm-cache/_cacache`、`NuGet/v3-cache` 下直属候选。不是整个 LocalAppData，不清理浏览器配置或持久数据库。 |

每个适用组的 `fzf` 首行是“清理当前组全部”，其后为真实直属候选。↑ / ↓ / Tab 移动，Enter 勾选 / 取消，Space 确认已选集；没有勾选时选定当前行并确认，有勾选时不额外加入当前光标项。搜索无匹配且无勾选时留在菜单；← / Esc 或失败不清理。选择完成仍会展示准确最终清单，按回车确认执行；输入任意非空内容（包括空格）后回车取消整个开发阶段并进入常规清理，输入结束或 Ctrl+C 取消整轮。首次显示首行不代表已授权删除。

退出分组后进入常规 clean；开发阶段普通异常或执行失败也会结束该阶段并继续常规清理，最后仍汇总开发阶段未完成结果，常规成功不会覆盖此前失败。EOF / Ctrl+C 立即停止整轮。常规只包含：用户 `Temp` 中至少七天未改动的直属项目；标准 PSReadLine 持久历史文件；目标实体已缺失且目标严格属于上述 Windows runner 开发输出的当前用户 Start Menu 快捷方式。开发缓存、AVD、构建输出和归档只在前置分组处理，跳过、取消和未选项不会由常规阶段补清。PSReadLine 历史先备份后移除，已打开的其它终端内存历史可能随后写回，本脚本不接管其它会话。常规类别的最终确认仍默认取消，选中“确认清理”后按空格执行。

常规用户缓存先用已有健康 fzf 明确选择：第一行“全选用户缓存”，第二行“跳过用户缓存清理”（默认焦点），下方可逐项勾选。Enter 勾选／取消，Space 确认已选集；没有勾选时选定当前行并确认，有勾选时不额外加入当前光标项。默认光标在跳过行时 Space 仍是跳过；搜索无匹配且无勾选时留在菜单。全选展开本轮完整候选，搜索不缩小其范围，跳过优先于全选，取消或失败不清理。选择后仍展示准确范围并沿用“选中确认清理后空格执行”的最终确认；无健康 fzf 时保留缓存且不自动安装。Windows 原生 fzf 控制台按键仍待目标机验收。

缓存直接删除，不经过回收站；请先关闭使用缓存的程序和构建。历史、AVD 登记、快捷方式和构建 / 归档输出先保存完整备份并校验内容，再移除原件；备份仍占空间，可按 `.restore.json` 中记录的原路径恢复，核对无覆盖风险后再处理备份。备份位于当前用户 LocalAppData 的 `Jobs/WindowsExtension/extensions/disk-space-info/clean-backups/<编号>`。

候选按内容通用识别保护，不依赖用户名、个人目录名或本机环境路径。标准工程／依赖目录（如 `.git`、`node_modules`、`Pods`、`.venv`、`site-packages`）、源码／SDK清单标记（如 `go.mod`、`package.json`、`Cargo.toml`、`pyvenv.cfg`、`package.xml`、`SDKSettings.plist`）或任意只读内容，都会使整项保留并说明原因，不自动提权或修改属性。每个候选流式扫描最多10,000个文件系统项、64层，扫描检查时间预算为5秒；超限或读取失败不生成不完整清理计划。该检查同时用于预览、执行前与暂存后复检。Windows目录挂载点／junction沿重解析点规则拒绝；不把MacOS设备号判断直接移植到Windows。

确认后重新发现候选。父路径、目标及子树中的重解析点、越界、权限失败、内容或清单变化都会保留或停止对应项目；缺失登记目标在备份前后再次核验。删除前先在原父目录暂存并复检；失败尽力移回原位置，无法移回时报告准确暂存路径，已删缓存不能因此恢复。受控错误汇总为未完成结果，其它已完成结果和备份保留，不以部分成功冒充全成功。

常规类别执行后若有失败，会列出剩余失败路径、类别、轮次与日志，并询问 `是否继续清理以上失败项？[回车 = 继续 / 输入任意字符后回车 = 停止]`。计划复检、备份或删除失败的具体异常原因直接显示在终端，执行中的错误同步追加到本轮日志，前置开发分组也沿用这一错误输出。回车只重试原确认清单中仍失败的项目，成功项目立即移出队列；每轮继续执行路径、原快照、备份和暂存复检，不纳入新候选。仍失败时再次询问；非空输入、输入结束停止整轮清理并返回失败，Ctrl+C 直接中断。前置开发分组仍沿用其精确选择和确认，不进入此重试队列；候选已变化时需退出后重新选择。

首次确认真实清理后才创建本轮日志，位置为当前用户 LocalAppData 的 `Jobs/WindowsExtension/extensions/disk-space-info/logs/clean-<编号>.log`。所有重试轮次、剩余路径和结果追加到同一份日志，恢复成功后按最终结果汇总。预览 / 取消不创建日志或备份。终端临时配色保护内嵌随包，支持能力检测、纯文本降级及结束恢复，不修改全局主题或 Profile。

原 `clean.command` 的历史 / 缓存 / 开发输出 / 失效登记 / 包管理清理 / 模拟器能力增删时，必须在同一维护任务同步本独立 Windows 实现及 [功能对照](../../README.md)。只对目标平台存在且能精确识别的能力做等价实现；Homebrew、LaunchServices、CoreSimulator 与 Spotlight 没有 Windows 同名能力，不为对齐清空注册表或正常设备。运行时始终不依赖原脚本。

隔离验证见 [CleanTests.ps1](../../Tests/CleanTests.ps1/README.md)。Windows 原生控制台按键、fzf、COM 快捷方式与 Explorer 点击仍需目标机验收。
